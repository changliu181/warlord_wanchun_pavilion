# warlord_wanchun_pavilion

三国战棋 —— 10x10 格子地图上的回合制对战小游戏，用 Pygame 写的小程序。
玩家一执红（蜀，南半场），玩家二执蓝（魏，北半场），双方轮流行动，把对方武将全灭即获胜。
既可以**两人同机对战**，也可以**一人游玩对抗电脑**——电脑现在有四个版本（见"六、电脑对手"）。

## 文件构成

| 文件 | 作用 |
| --- | --- |
| `warlord.py` | 游戏本体：武将、对局规则、交战结算、绘制、主循环 |
| `constants.py` | 全局常量与配色（屏幕尺寸、地形、规则数值、电脑版本注册表）——改平衡看这里 |
| `config.py` | `map.txt` / `generals.txt` 的解析与校验 |
| `stratagems.py` | 计谋的规则层：成功率、合法目标、四种效果（不 import pygame，可单独测） |
| `ai.py` | 电脑对手的**分派层**：按"此刻该做决定的那一方"把调用转给对应版本（驱动器 + 交战屏状态机） |
| `mei/` | 电脑**「梅」版**——参照版，冻结不动。一整套：`knobs.py`（通用性子）+ `tactics.py` / `defense.py` / `offense.py` / `ai.py` |
| `ju/` | 电脑**「菊」版**——升级版（当前主力，搜索调大 `BEAM=16`/`DEPTH=4`）。结构与 `mei/` 完全一样 |
| `lan/` | 电脑**「兰」版**——从 `ju/` 复制而来（保留 `BEAM=8`/`DEPTH=3`），供独立迭代。结构与 `ju/` 完全一样 |
| `zhu/` | 电脑**「竹」版**——从 `ju/` 复制而来（搜索调小 `BEAM=4`/`DEPTH=2`），供独立迭代。结构与 `ju/` 完全一样 |
| `replay.py` | 对局录像：边打边写 JSONL 到 `replays/`；也是看录像的查看器（文字复盘 + 图形复盘，见"七、对局录像"） |
| `smoke_test.py` | 无头回归测试：两个电脑对打整局，跑规则和电脑判断的改动 |
| `ai_match.py` | 无头对战统计：两个电脑版本互相对打，报"A 对 B 的胜率"（验证升级有没有生效） |
| `ai_time.py` | 无头算力统计：几版两两循环赛，报每版 AI 自己花掉的计算时间（比较各版的开销，见"六"） |
| `stratagem_test.py` | 计谋的无头回归测试：算式、合法目标、代价、四种效果 |
| `map.txt` | 固定地图配置（地形 + 地名写在一起，不标出生点） |
| `generals.txt` | 武将配置（双方各 20 名，武力 / 智力都是固定值） |

### 电脑为什么拆成多个包

把电脑当"一个可以升级的东西"来养：

* **梅**（`mei/`）是**稳定参照版**，冻结不动——它的代码和旋钮永远不改，只当基准；
* **兰**（`lan/`）是**升级参照版**，也已经冻结不动，只当基准；
* **竹**（`zhu/`）是**当前的实验位**—力争做到95%以上对兰胜率；
* **菊**（`ju/`）是**升级版**——未来下一步提水平就只动这一个包；
  只是各占一个独立的包，供分别试新想法（互不干扰）。**此刻三版已被拉开差距**：
* 各包**互不 import**，各带自己那一整套旋钮（通用性子在 `<版本>/knobs.py`，
  进攻的 `KILL_W` 那批在 `<版本>/offense.py` 顶部，防守的 `OWN_*` 在 `<版本>/defense.py` 顶部），
  所以改一版不会牵动别版；
* 固定梅、兰，升级竹和菊，然后跑 `ai_match.py` 看**竹对兰的胜率**——过了 95% 才算真的升级。
  这就是"AI 到底有没有变强"的判据：不看改动大小，只看对稳定版本的胜率。

顶层 `ai.py` 只负责**分派**：按"此刻该做决定的那一方"取版本。交战屏上攻守可能属于不同版本
（菊 vs 梅 就这么打），所以"谁先出阵 / 打还是撤 / 往哪撤"归守方那一版算、"继续还是收手"归
攻方那一版算——两边各用各的账，不会串味。

## 运行方式

安装 Pygame 后直接运行：

```
pip install pygame
python warlord.py
```

启动后先进**模式选择屏**：选一人游玩（对抗电脑）还是两人同机；选了"一人游玩"再选
执蜀还是执魏，最后选**电脑用哪个版本**（梅 / 兰 / 竹 / 菊）。改完规则 / 改完某一版的电脑想验一下，
跑这几个无头脚本（不用开窗口）：

```
python smoke_test.py         # 两个电脑对打整局，看规则改动有没有把局面带歪（两边都用梅）
python smoke_test.py --draw  # 顺便把整局画一遍，检查绘制路径
python ai_match.py           # 菊 vs 梅 打 20 局，报菊对梅的胜率（验证升级）
python ai_match.py --games 100   # 多打几局，胜率才稳
python ai_time.py            # 几版两两各打 6 局，报每版 AI 自己花的时间（比较开销）
python ai_time.py --a 竹 --b 兰 --games 10   # 只打一对
python stratagem_test.py     # 计谋这一块（算式、目标、代价、效果、界面自检）
python replay.py replays/xxx.jsonl   # 看一局的复盘录像（见"七、对局录像"）
python replay.py replays/xxx.jsonl --gui   # 开窗口一步步看棋盘（← → 前后翻一步）
```

有电脑参与的局都会自动留一份录像到 `replays/`（Python 3，标准库，没别的依赖）。

配置在**开局时**读取并校验，有问题不会进主界面，而是弹出一个小窗把出错原因和配置文件路径写出来
（两份配置：`map.txt` 地图（含地名）、`generals.txt` 武将）；
游戏中按 R 会回到模式选择屏重新选，选完才发现配置被改坏的话，会保留当前对局并在战报里提示。

## 一、地图（map.txt）

地图写在 `map.txt` 里。**地形和地名写在同一个文件里**：一格一项，
可通行格写成 `地形:地名`，障碍格只写 `#`。

地形图例（冒号前面的那一个字符）：

- `.` 通路：可通行
- `#` 障碍：不可通行，也不能穿过去
- `C` 城池：可通行，驻守回血更多（+3，通路只有 +2），守城时交战有体力加成（见"交战"）

举几个格子的写法：`.:樊城`（名叫樊城的通路）、`C:襄阳`（名叫襄阳的城池）、`#`（障碍格，没有地名）。

地图配置的硬性要求（`parse_map` / `validate_map` 会逐条校验）：

1. 去掉以 `//` 开头的注释行和空行后，必须**正好 10 行**、每行**正好 10 项**。每格算一项，项与项之间必须有空白——地名长短不一，所以不能再写成 `. . .` 和 `...` 那样紧凑的字符形式。
2. 可通行格一律要写成 `地形:地名`，**一格都不能漏**；障碍格只写 `#`，不能给它起名。
3. 地名不能重复：整张地图里每个地名只用一次。
4. 城池必须**正好 10 座**（数量由 `constants.py` 的 `CITY_COUNT` 决定），城池那一格写成 `C:城名`。
5. 所有通路 / 城池必须**连成一片**，不能有走不到的孤岛格。
6. 开局时玩家二（魏）的武将随机落在北半场（前 5 行）、玩家一（蜀）的随机落在南半场（后 5 行）的通路或城池上，所以**南北半场各自至少要有自己那份上阵人数的可通行地形**（上阵人数看 `DEPLOY_COUNT`，南北半场由 `SPAWN_ROWS` 决定）。

### 当前这张地图的设计

上北下南：北半场是魏，南半场是蜀与吴。

- 10 座城池：邺 (0,7)、长安 (1,2)、洛阳 (2,4)、合肥 (3,8)、汉中 (4,1)、襄阳 (4,5)、江陵 (6,5)、建业 (6,9)、成都 (7,1)、长沙 (9,5)。共 54 格可通行（上半场 27 / 下半场 27）。
- 注意**第 4 行还在北半场**（`SPAWN_ROWS` 把前 5 行划给魏），所以汉中 (4,1) 和襄阳 (4,5) 开局都在魏手里：北半场 6 座城、南半场 4 座。但先手方是蜀，所以这是基本平衡了的。
- 城池之间这些通路是通的：汉中—长安（两条互不共格）、长安—洛阳、洛阳—邺、邺—合肥、洛阳—合肥、洛阳—襄阳、汉中—襄阳、汉中—成都、成都—江陵、襄阳—江陵、江陵—长沙、江陵—建业、建业—合肥；另外同一块地皮还顺带连着襄阳—邺、襄阳—长安、合肥—襄阳、合肥—江陵、合肥—长沙、建业—长沙、成都—长沙。

改完地图保存，游戏里按 R 回到选择屏、重开一局即可按新地图生效（也会重新随机分配出生点）。

### 地名

地名就写在每格冒号后面（城池那格写的就是城名），和地形一起在 `map.txt` 里。

地名按"上北下南"的三国地理起：北半场是魏（河北 / 关中 / 中原 / 淮南），南半场是蜀与吴
（巴蜀 / 荆州 / 江东 / 荆南）。一条道上按顺序排，比如关中—汉中那条是
五丈原 → 陈仓 → 斜谷 → 箕谷 → 褒中，江陵—建业那条是长江顺流
夏口 → 柴桑 → 采石；每条道的完整地名排列写在 `map.txt` 顶部的注释里。

地名显示在哪些地方：

- **地图上**：每格底部写着地名——通路是青灰色，城池是金色。武将站在某一格时，字会被武将牌压住。
- **鼠标悬停**：停在任意格子上都会弹出该格的「地名（地形）」，「被武将压住的地名」这样就能看。
- **侧边栏**：选中武将时，"位于 ……" 显示的就是他所在格的地名。
- **战报**：移动、进攻、进占都会写成地名，比如"关羽 移动 2 格至 樊城（通路）"。
- **交战界面**：标题下写明交战发生在哪一格（如"驻守的 襄阳（城池）"），左右两张卡片上也标着
  攻方从哪一格打过来、守方驻守在哪一格。

改完保存，游戏里按 R 回到选择屏、重开一局即可生效。

## 二、武将（generals.txt）

格式是每行 4 项：`<阵营> <姓名> <武力> <智力>`，例如 `蜀 关羽 21 14`。

- 阵营：`蜀` = 玩家一（红），`魏` = 玩家二（蓝）。
- 武力 / 智力：1-22 的整数。**武力决定战斗判定权重和伤害，智力决定计谋的成功率和效果。**

校验要求：去掉注释行和空行后每方**正好 20 名**；同一方内姓名不能重复（两方之间可以重名）；
武力 / 智力必须落在 1-`MAX_STAT`（22）之间。

开局时每方从本方 20 名里**随机抽几名上阵**（人数看 `DEPLOY_COUNT`，两边可以不一样多），抽中的武将再随机落到本方半场的通路或城池上（障碍格不能站人）。
抽将和选出生点都用同一个随机数发生器，所以按 R 重开会重新抽将、重新站位——**同一张地图每局站位都不一样**。

改完保存，游戏里按 R 回到选择屏、重开一局即可按新配置重新抽将。

## 三、核心定义与规则

### 地形

地形用整数枚举定义：`OBSTACLE = 0`（障碍）、`PLAIN = 1`（通路）、`CITY = 2`（城池）。
增加第 4 种地形（比如"树林"），只需在 `TERRAIN_*` 常量后面追加，并把 `TERRAIN_NAME` / `REGEN` 里各补一条即可，其余逻辑会自动跟上。

### 武将属性

- **武力 might**：固定值，1-`MAX_STAT`，决定**交战每回合掉多少体力**（掉血只看对方的武力）。
- **智力 intellect**：固定值，同样是 1-`MAX_STAT`，决定计谋的成功率和效果。
- **体力 stamina**：可变值，上限 100（`MAX_STAMINA`）。**交战和计谋等多种情况会消耗体力**，体力归零即阵亡。
- **移动力 move_points**：每回合重置为 3（`MOVE_POINTS`）。挪到相邻一格花 1 点，发动进攻也花 1 点（打不赢又收手撤退的话，还要再补 1 点），所以一回合最多走 3 格。

### 移动

一回合最多走 3 格，走多格可以一次点到位（底层用 BFS 算出每格要花的最少移动力）。
**移动力与体力完全脱钩**：移动不消耗体力，体力见底也能照走 3 格；反过来，移动力耗尽的武将（界面上会盖上灰罩）本回合既不能走也不能交战。

**一格最多站两名武将**（`CELL_CAPACITY`），而且**只有同一阵营能同格**——敌我永远不会站在一格上。
由此分成两件事：

- **能不能停在那一格**：己方在那里不足两名就行；敌方格永远不能停（走进去等于交战）。
- **能不能从那一格穿过去**：只要是通路 / 城池、且没有敌方，哪怕那格己方已经站满两名也能路过。
  所以自家两个人堵住的通道不会把第三个人卡死——**只看终态有没有超员**，不看中途踩过谁。

障碍格既不能停也不能穿。同一格站了两名己方武将时，棋盘上**左右分栏**各画一半
（三字姓名会自动缩小字号塞进半格；半格放不下属性行，悬停提示和侧边栏里还有）。

**选中了武将之后，点高亮格就是走过去**——哪怕那一格上已经站着一名己方武将（还有位置就能停）。
这正是"一格能站两人"的用法：先把甲挪到乙所在的格上，两人并肩。
想改选站在落脚点上的那位时，先点自己的武将取消选中，再点那一格。
同一格有两名己方武将时，连点那一格会在两人之间轮换，轮完最后一个再点一下就是取消选中。

### 回合制

双方轮流行动，只要移动力还没花完，这名武将就能**继续行动**（继续走、或者继续撞下一个人）；
移动力花完了本回合才动不了。空格或回车结束回合，换对方行动。总回合数上限 100（`TURN_LIMIT`，双方各行动一次算 2 回合）。

每回合**结束时**，刚刚行动完那一方的存活武将按**所在地形**恢复体力：
通路 +2、城池 +3、障碍 0（地形上本来也站不了人）。

如果这名武将上回合**作为守方撤退过**，新回合开始时先扣掉透支的行动力（见下面"撤退"）——移动力在回合开头重置。攻方撤退是当场付清的，不留隔夜账。

### 交战

把己方武将的移动目标点成"**相邻的**敌方武将格子"（踏进去）即触发交战，消耗 1 点移动力
（`ATTACK_COST`）。必须从相邻格踏入，不能隔着格子冲锋。进攻方在交战期间**不动窝**：
打退守军、就地进占，账就结清了，总共只花这 1 点；半路收手撤退则要再补 1 点（见下面"撤退"）。

触发后游戏会切到**单独的一屏**（交战界面）打单挑，胜负判定和伤害结算都在这一屏上完成。

#### 守军有两名时：谁先迎战

一格站两名守将时，攻方踏进来后**由守方点将**，决定谁先出阵，另一位排在后面。
攻方把第一名守将打完（**撤退或阵亡都算**）之后，只要这一格还有守将，就自动接着打第二名。

**第二场开打前，双方都可以先选择撤退**（仍是攻方先选）——这时攻方已经打了一场、
守方却是生力军，给两边一个收手的机会。第一场没有这一步，仍然要打满 1 回合才能撤。
界面上会标出"第 N 场 / 共 N 场"，战斗过程里两场的回合也分开记。

#### 交战界面的规则

- **每回合双方同时掉体力**，掉多少只看**对方**武力：取闭区间 `[1, 2 * 对方武力]` 里的一个随机整数
  （上限系数是常量 `LOSS_MAX_PER_MIGHT`）。武力高的武将打得疼，同时也更扛打——因为对方的武力决定了他要掉多少。
  体力 100、武力 20 的武将对砍，平均每回合掉 20 出头，所以单挑通常三五回合见分晓。
- **每回合结束时双方都可以选择撤退**，由**攻方先选**（攻方先选完才轮到守方）。选择撤退的一方算**败方**。
  两边都选继续才进下一回合，所以**交战至少打满 1 回合**，撤退最快也要等第 1 回合打完才能选。
- **体力掉到 0 或以下即阵亡**，同样算败方；双方同一回合都掉到 0 就是**同归于尽**（这局单挑算平局）。
- **打完时双方剩多少体力，就是这场交战的伤害结算结果**——没有额外的伤害公式。

#### 撤退

撤退不只是在原地让位，而是要**真的挪走**。两边的规则不一样：

- **攻方撤退**：人还是站在出发格不动，但要**当场再补 1 点移动力**（`ATK_RETREAT_COST`）——
  所以"打一半收手"总共花 2 点（进攻 1 点 + 撤退 1 点），而**打赢了只花 1 点**。
  攻方**不赊账**（没有"透支"一说）：手头不够这 1 点的，界面上干脆不给"撤退"按钮，只能接着缠斗。
  换句话说，带着 1 点移动力撞上去的武将，是**没有退路**的——要么打赢，要么殉国。
- **守方撤退**：要自己挑一个**落脚点**撤过去，界面上把每个能去的格子列成一个按钮
  （写着地名和这次要透支几点），步数就是 BFS 算出来的最短距离。
  **退几格就透支下回合几点行动力**，而**同一回合累计撤退格数封顶 `MOVE_POINTS`**：
  退满 3 格，下回合这名武将就走不动了。
  已经撤过的格数会占掉额度——同一个回合里被连着打退，第二次能退的距离就变短；
  **额度不够的撤退不算合法**，那些落脚点根本不会出现在按钮里；额度耗尽后连"撤退"按钮都不给。

撤退走的是 **BFS 路径，可以拐弯，不要求走直线**——先往东一格再往南一格是允许的。
约束是：

- **第一步不能迎着攻方来的方向**——那是朝刀口上撞（攻方站的那一格本来就过不去）。
- 中途每一格要**过得去**：通路 / 城池、没有敌方。和移动一样，己方站满两人的格子可以**穿过**。
- 落脚的那一格还要**停得下**：己方没占满 `CELL_CAPACITY`。所以两个守将可以先后撤到同一格。
- **一个落脚点都没有时，守方就没有撤退的权利**：交战界面上干脆不给"撤退"按钮，只能继续缠斗。
  没有落脚点有两种情形——周围无处可退，或者**本回合撤退额度已经用满**。
  （所以"想撤却无处可撤"这种情况不会再出现，攻方也就能稳稳进占。）
- 只有一个落脚点时不用再点一次，直接撤。

#### 战果落回地图

- **守军被打光**（都撤退或阵亡）且攻方自己没退没死：攻方进占这一格。
- **守方守住**（攻方撤退，或攻方阵亡）：攻方原地不动。
- **同归于尽**：两边都从棋盘上消失，格子空着。

交战不结束进攻方的行动：只要还有移动力，他就能接着走、接着撞下一个人。
被撤退"透支"的只有守方的下回合行动力，不影响攻方。

> **关于城池**：城池加成是**临时**的——开打前守军体力 ×1.2（四舍五入），打完 ÷1.2 还原。
> 两次取整在 0-120 内可以精确还原，所以没受伤的守军血量分毫不差，只是**打的过程中**多扛 20%
> （体力 100 的守将顶到 120，实际多扛 20 点）。这条只对**防守方**生效，而且守的那一格是城池才算。
> 城池同时还是回血更快的据点、以及地盘分里最值钱的一格（城池 3000 分，通路只有 200 分，
> 见"胜负"）。

守城加成让"啃城"明显变贵：同样是 100 体力的守将，守城时你要多打掉 20 点才算赢。

### 粮草

粮草的作用是**用机动力吃粮草换体力**。

**产出**：**每 5 个回合入库一次**，落在 **4 / 9 / 14 / 19 …**（回合数 `% 5 == 4`）这些回合的
**开头**，其余回合不产粮。到点的时候每座城池产 1 石，堆在城池那一格上，
所以一批就是全场 10 石（10 座城池各 1 石）。一局 100 回合下来共 20 批、200 石，
开局后，第 4 回合才见第一批粮。侧边栏回合数旁边写着「下批粮草 第 N 回合」，
不用自己数。产出不看城池归谁占着——粮草**没有归属**。

**堆在格子上**：格子右上角会挂一个 `粮N` 徽标。格子对粮草**没有容量上限**，
没人取就一直涨（全局也是）。

**搬运**：**武将只是脚夫，不是粮仓**——身上不存粮。点目的地时，如果**出发点堆着粮草**、
走的又是人类玩家，会先弹出「携带粮草」问一句搬多少：可选 `－10 / －1 / ＋1 / ＋10` 微调，
或「不带」「全带」两个快捷，确定后才落子（ESC 或「取消」就当没走过这一步）。

**搬多少没有上限**，想一次搬空一座城也行；但**走到目的地就当场卸下**，
并入那一格的粮堆。所以一次「搬运」的净效果就是：**把粮草从出发格挪到落点格**。
带多少都**不影响移动力**，也不影响别的任何数值。

这个设定有两个后果：

- **要往远处送，就得一格格接力**。这一回合搬到半路，下一回合站上去再取一次接着搬。
  中间随便哪个己方武将路过，也能顺手接过去——粮草没有归属，谁站上去都能取。
- **武将身上永远没有粮草**，所以"带着军粮打仗、打输了被缴获"这种事不会发生。
  粮草始终躺在格子上，谁最后站在那一格，谁就攥着它。

**吃粮**：武将和粮草在同一格就能吃，一口吃 1-3 石，**吃几石就花几点行动力**，
1 石回 10 点体力。选中武将后详情框底部会出现 `吃1石 / 吃2石 / 吃3石` 按钮；
能吃到几石取决于三个上限：一口最多 3 石、**脚下**得有那么多粮、还得有同样多的剩余移动力。

所以运粮是有意义的：把城里的粮搬到前线，武将站上去就能在野外回血。

**交战不涉及粮草**：粮草从不带在武将身上，所以攻城、撤退、阵亡都不会让粮草易主——
争夺格上那堆粮原地不动，只是守将走了、攻方站上来了，下一次取粮的人变成了攻方。

### 计谋

智力的主要用途。选中己方武将后，侧边栏的详情框里第二排有一颗**「用计」**按钮，
点开弹窗从四条计谋里挑一条；挑完弹窗关掉、进入**瞄准态**：棋盘上凡是能点的目标都染成紫色，
点一下当场掷骰结算。弹窗里挑来挑去**不花钱**，代价是在瞄准态**点了目标**的那一刻才结的。

**代价**：1 点行动力 + 10 点体力（`STRATAGEM_MOVE_COST` / `STRATAGEM_STAMINA_COST`），
两样缺一不可，而且**不论成败照付**——扔出去的谋略没有收回来的。
体力卡的是**多于 10** 而不是"至少 10"：正好 10 点的话付完就归零，那是阵亡，等于用计自尽；
所以留 1 点底，弹窗里会写清楚为什么开不了。

四条计谋，成功率一律**夹在 0~1 之间**（系数都在 `constants.py` 的 `STRATAGEM_*` 里）：

| 计谋 | 目标 | 成功率 | 效果 |
| --- | --- | --- | --- |
| **暗度陈仓** | 一个能落下的格子 | `智力 / 25`（只看自己） | 跃过**紧邻的那一格障碍**，落到正对面两格处。四个正方向都行；落点按普通规则判（不能有敌方武将、己方不足 `CELL_CAPACITY`） |
| **调虎离山** | 3 格内的敌将 | `(我方智力 - 敌方智力 - 6) / 8` | 把中计的敌将**牵着走**一段。上限 `min(floor((智力差 - 2) / 2), 6)` 格，掷出一个 `[1, 上限]` 的随机数当这次的额度，然后**由用计方点一个落脚点**（额度以内任选） |
| **内讧** | 3 格内的敌将 | `(我方智力 - 敌方智力 - 8) / 8` | 再点一名敌将（和第一个目标**同格或相邻**），两人自相残杀**一回合**：各按对方武力掉血，可能当场阵亡；**谁都不挪窝** |
| **劫粮** | 一处有粮草的格子 | `(我方智力 - 敌方智力) / 20` | 把那一格上的粮草**全部**搬到用计方的脚下 |

几条细节：

- **射程按欧氏距离算**（格子中心到格子中心）：正交 3 格刚好在射程上，斜着 `(2,2)` 也算，
  `(3,3)`（4.243）就出界了。
- **"敌方智力"怎么取**，规则里分两套，`stratagems.py` 里各封了一个函数：
    - 对**敌将**用计（调虎离山 / 内讧）：单独站一格就是他自己；同格另有**智力比他高**的同伴时，
      取两人智力的平均值（同伴智力比他低就不算数）。
    - 对**格子**用计（劫粮）：格上没武将、或只有己方武将，按空场值 `10` 算；
      有对方武将就取格上敌方武将里**最高的**那个智力。
- **成功率算出来是 0 的目标不会摆出来**（智力差不够就别浪费代价了），同样地：
  调不动格数的敌将、边上凑不出第二个人的敌将、场上没别处的粮，都直接不列。
- **调虎离山把人牵走时，不看他自己的移动力**——他是被牵着走的，不是自己行动，
  这回合还剩几点都不影响。
- **内讧不算守城加成**：他俩是在自家人堆里互砍，不是在据城防守。
- **代价从用计方身上扣**，扣完还剩行动力的话可以接着走、接着打——和移动、进攻共用同一份移动力。

界面上：瞄准态棋盘下沿有一条提示写着现在该点哪里，`ESC` 收手（**只有还没扣代价时管用**）；
内讧挑第二个人、调虎离山挑落脚点这两步是"计谋已经成了，把结果摆完"，不能反悔。
战报里会写清成功率和掷出的点数，例如
`🎴 诸葛亮 对 剑阁（通路） 用「调虎离山」：成功率 75%，掷出 31—— 得手！`。

> **当前几版电脑AI不会用计谋**。规则和界面都是齐的，但 `<版本>/ai.py` 里还没做计谋决策，
> 所以 1P 模式下电脑只会按老一套走位、进攻、吃粮。

### 胜负

- 一方武将全灭即败；双方同时全灭算平局。（单挑里的"同归于尽"只让那两名武将一起下场，
  只有棋盘上某一方真的一个不剩，整局才结束。）
- 回合数达到上限时按**总分**比较，总分 = **将领分 + 地盘分**：

  | 分项 | 算法 |
  | --- | --- |
  | 将领分 | 本方每名**存活**武将各算 `(100 + 体力) × 武力`，逐名求和 |
  | 地盘分 | 每块可通行地域归**行动距离最近**的那一方：城池 `3000`、通路 `200`，外加格上粮草每石 `150` |

  **行动距离**是 BFS 步数：从这一方所有武将同时往外走（多源 BFS），每格取最近的那名武将，
  只在通路 / 城池上量（障碍得绕路），**格上站着谁不影响**——量的是"这一方的兵要几步才能到这儿"，
  不是"现在谁能站上去"。所以地盘是**动态**的：往前压一步，身后一大片就跟着易主。
  两边一样近的格子算**争夺中**，谁也不算——比分板上会单独报一句「争夺中 N 格」，
  免得两边地盘加起来对不上整张图。

  粮草是"格上的物品"，算在**控制那一格**的一方头上：城池产的粮堆在城里，谁控制了这座城，
  连同堆里的粮一起算分（所以把前线的粮搬回家、或者反过来把粮堆留给对方，都会直接影响比分）。

- **比分板常驻在侧边栏**（"选中武将"详情框右边），一局自始至终显示双方的总分 / 将领分 / 地盘分，
  随时能看出谁领先。回合用尽时战报里也会再报一次明细。

| 旋钮 | 位置 | 作用 |
| --- | --- | --- |
| `AI_KILL_WORTH` | `<版本>/knobs.py` | 打死一名敌将，按他身价的几倍算（死人不会再回来赚分、守土） |
| `AI_DEATH_WORTH` | `<版本>/knobs.py` | 自己可能被打死的风险折算（按身价的这个比例扣分） |
| `AI_THREAT_WORTH` | `<版本>/knobs.py` | 站在刀口下、又退无可退时的追加扣分 |
| `AI_SIEGE_WORTH` | `<版本>/knobs.py` | 堵断敌人退路的"铺垫"值多少分（退路一断，下次开打就是歼灭） |
| `AI_CITY_PULL` | `<版本>/knobs.py` | 落脚点本身的分（地形分 + 粮草分）按几成计入走位分 |
| `AI_DEBT_WORTH` | `<版本>/knobs.py` | 撤退欠下的一点行动力值多少分 |
| `AI_GRAIN_CARRY` | `<版本>/knobs.py` | 走位时最多顺路搬几石粮（搬 = 从出发格挪到落点格） |
| `KILL_W` / `LINE_W` / `ADVANCE_W` / `ATTRIT_W` / `THREAT_W` | `<版本>/offense.py` 顶部 | 进攻：杀将 / 拉锯线抱团 / 向敌推进 / 有利消耗 / 挨打风险 的权重 |
| `IDLE_EDGE` / `BEAM` / `BRANCH` / `DEPTH` | `<版本>/offense.py` 顶部 | 进攻：动一步的门槛、模拟规划保留几条分支、展开几个动作、往前看几名武将 |
| `OWN_TIE` / `OWN_SCALE_WORTH` / `OWN_TURN_SD` / `Q_*` / `NEAR_CELLS` | `<版本>/defense.py` 顶部 | 防守：**谁先出阵 / 往哪撤**（归属概率那一套）——打平的归属、落脚点的分、到达时间的分布 |
| （梅版还有）`OWN_DEFEND_TOP` / `OWN_HOLD_EDGE` | `mei/defense.py` 顶部 | 梅版的"打还是撤"那条线（菊版已换成两条硬条件，**没有可调旋钮**） |

**关于 `LOSS_MAX_PER_MIGHT = 2`**：交战每回合的掉血是 `[1, 2 * 对方武力]` 里的随机整数，
所以双方每回合至少各掉 1 点——体力 100 的武将**最迟 100 回合必定分出胜负**，单挑不会无限拖下去。
把系数调小，单挑会变长、更看运气；调大则更快见分晓。`Battle` 类里另有几个**只影响表现、不影响规则**的常量：
`IMPACT_FRAMES`（掉血动画帧数）、`HIST_ROWS`（战斗过程一屏显示几回合）。

## 五、操作

### 地图上

- **鼠标左键**：点高亮格移动（**点了就是走过去**，那一格上站着己方武将也能走）/
  点自己的武将换选（同格有两人就轮着选，轮完再点一下取消选中）/
  点相邻的敌人格子发动进攻 / 点侧边栏按钮（`吃粮` / `用计`）
- **空格 或 回车**：结束回合
- **滚轮**：鼠标放在武将总览上时，上下翻看没显示出来的武将（人少时不用翻）
- **R**：回到模式选择屏重开一局（重新读取 `map.txt` / `generals.txt`，重新抽将）
- **ESC**：退出

**用计**（规则见上面「计谋」一节）是两段式操作：

- 详情框第二排的 `用计（1 行动力 + 10 体力）` 按钮打开弹窗，里面按 `1`~`4` 或鼠标点选一条计谋，
  按 `ESC` 取消。付不起代价时这颗按钮画成暗色，点了只提示一句为什么。
- 挑完进入**瞄准态**：棋盘上能点的目标染成紫色，点一下当场掷骰结算；棋盘下沿有提示条
  写明现在该点哪里。**按 `ESC` 收手**——这时代价还没扣，等于没用过。
- 内讧挑第二个人、调虎离山挑落脚点这两步**不能反悔**（计谋已经成了，得把结果摆完）。

选中己方武将时，侧边栏详情框里会多出一排 `吃1石 / 吃2石 / 吃3石` 按钮——
前提是这名武将**脚下有粮**而且还有移动力，点一下就吃。

**点高亮格移动时，如果出发点堆着粮草，会先弹出「携带粮草」**（见"粮草"一节）：
`←/→` 减/加 1 石、`↓/↑` 减/加 10 石，回车或空格是确定，ESC 是取消。
搬多少就卸多少在落点，想空手走就点「不带」再确定。

**轮到电脑时键盘鼠标都不接**（侧边栏会写"电脑思考中…"，并标明是哪个版本），只有 R 和 ESC 照样管用。
交战屏上也是一样：谁的回合谁做决定——电脑进攻你驻守的那一格时，
"谁先出阵""继续还是撤退""往哪撤"还是由你点。

### 交战界面上

交战是单独的一屏，进入后**键盘鼠标都归它管**（战斗期间 ESC / R 故意不生效，免得打到一半误触把这一局丢了；关窗口仍然可以退出）。

- **鼠标左键**：点按钮。按钮随阶段变化：
  - `交手` —— 双方同时扣体力，放掉血动画，然后进入选择阶段
  - `继续缠斗` / `撤退（判负）` —— 该方选择是否继续打（先攻方、后守方）。
    攻方那个按钮写着 `撤退（判负，再补 1 点）`，提醒这一退要额外花 1 点移动力。
    退不了的一方只给"继续缠斗"、"撤退"按钮不出现——守方是**无处可退、或本回合撤退额度已用满**，
    攻方是**手头的移动力不够补那 1 点**
  - `X 先出阵` —— 一格有两名守将时，**由守方点将**决定谁先迎战
  - `撤至 陈留（2 点）` 之类 —— 守方点了撤退、且不止一个落脚点可去时，
    把每个能撤到的格子列成一个按钮（括号里是这次要透支的行动力，
    本回合累计不能超过 `MOVE_POINTS`）；
    旁边还有 `再想想（回去缠斗）`
  - `返回战场` —— 打完收工，回到地图
- **空格 或 回车**：等同于点第一个按钮（交手 / 继续缠斗 / 返回战场），不会误触"撤退"。
  **点将和挑落脚点那两屏例外**：那里的按钮都是"替自己做决定"，
  按空格什么都不做，必须用鼠标点
- **滚轮、↑ ↓、PageUp / PageDown**：翻看战斗过程（回合数多了以后可以往回翻）

交战界面左右两张卡片是攻守双方（姓名、武力智力、体力条、本回合的掉血范围、该谁做决定），
卡片右上角标着攻方从哪一格打过来（如"从 樊城（通路） 进攻"）、守方驻守在哪一格（如"驻守 襄阳（城池）"），
标题下也写着交战地点（守军两名时还会标出"第 N 场 / 共 N 场"），中间显示回合数，
下方"战斗过程"逐条列出每一回合双方各掉了多少、还剩多少体力——**两场的回合分开记**，
换人之后也会把上一场的守将名字正确留在历史里。守方卡片上还会写"阵中还有：某某"，提示后面等着谁。

界面右侧面板显示回合数与当前行动方；右边一行并排两块**常驻**的小面板：
左边是选中武将的详情（武力 / 智力 / 体力 / 移动力 / **所在地** / 脚下粮草，所在地写的是地名，
如"位于 襄阳（城池）"），右边是**比分板**（双方的总分 / 将领分 / 地盘分，算法见"胜负"，
标题右边还会报一句「争夺中 N 格」）。下面是战报和双方武将总览（**一栏一方并排**，阵亡的会标注；
两边上阵人数可以不一样多）。
总览一屏最多显示 `ROSTER_MAX_ROWS`（7）行，**上阵人数更多时变成可滚动的窗口**：把鼠标放在总览上滚滚轮翻看，
右边有一根滚动条，标题旁边写着「武将 1-7/14 滚轮翻看」。这样人再多也不会把上面的战报挤掉——
**战报区恒定留 4 行**，不随人数变化。
棋盘上每格底部写着地名（通路青灰、城池金色），黄色高亮是能走到的格子，红色高亮是能发动进攻的敌人格子，
鼠标悬停在任意格子上会弹出该格的「地名（地形）」——武将站在格子上时地名被压住，这样就能看。
同一格站两名武将时棋盘上左右分栏各画一半。

## 六、电脑对手

一人游玩时，另一边由电脑操控。它**只用手头这个局面**做判断，不偷看未来，也不需要预演整局；
每走一步都在主循环里暂停 `AI_STEP_FRAMES` 帧，所以你能看清它把谁挪到哪、什么时候冲锋——
侧边栏在它思考时会写"菊版思考中…"这样的一行，它的每一步也都进战报。

电脑有**四个版本**：「梅」「兰」「竹」「菊」。
开局选"一人游玩"时最后会问一句用哪个版本；
拆出来是为了各自独立迭代，再用 `ai_match.py` 评测胜率
（见开头的「电脑为什么拆成多个包」与「四版基准评测」）。

决策按"这一轮是我进攻还是我在挨打"分成两半，**每个版本包里**都这么拆：

- **进攻回合策略**（`<版本>/offense.py`）：这一轮全军怎么动——回合级模拟规划，先动谁、后动谁、
  甲一步乙一步，都在搜索树里比过；
- **防守回合策略**（`<版本>/defense.py`）：被打到一格、轮到自己做选择时"打还是撤、打到什么程度撤"。

两边共用同一套推演原语（`<版本>/tactics.py`：单挑赛跑、身价、格子价钱、撤退路径、强攻推演）。
一版内部依赖单向 `tactics.py <- defense.py <- offense.py <- ai.py`；两版之间**互不 import**，
由顶层 `ai.py` 按"该做决定的那一方"分派。进攻策略里预判"下一回合对方进攻时我方难啃 / 会不会
丢人"，用的就是同一版防守策略那套归属概率——防守怎么想，进攻就照着防。

### 它在棋盘上做什么（`offense.plan_step`）：**回合级模拟规划**

它不再"给每名武将各挑一步"，而是把**整个回合**当成一盘棋来模拟：

1. 一个候选 = 让某名还有移动力的己方武将走一件**有意义的动作**（强攻 / 吃粮 / 走到
   关键落脚点），落在局面的**副本**上（真局面一个字节都不动）；
2. 子节点 = 新副本上让别人接着动，所以"甲走一步、乙走一步、再甲走一步"这种**交错走法**
   都在搜索树里；每个节点按三条目标打分，宽搜 + 剪枝取最优；
3. **一次只落实第一步**（`plan_step` 只返回一个动作），走完再重新规划——所以
   "打完一仗就重新规划"是天然的：仗一打完局面变了，下一步重新搜；
4. 搜到"谁都动不了"或"再动也没实质收益"（`IDLE_EDGE`）为止，剩下的移动力宁可不要
   （不为了动而动），这时才**收工**把回合交给对方。

每一步都真的花掉移动力或者收工，所以一个回合内必然收敛。电脑**不走**"弹窗问带多少"那条路
（那是给人类玩家的），它搬多少是直接算好的（`AI_GRAIN_CARRY` 石）。

### 它在交战屏上做什么（`ai_battle_step`）

- **守方的"打还是撤"**（`defense.ai_should_hold`）：这是**防守回合策略**的核心。

- **谁先出阵**（它是守方时，两版同）：同格守将一位一位上，前一位顶不住会磨掉攻方一轮血。它把两种出场
  顺序各按归属概率推演一遍，挑**本格守得最稳**的那种排法（谁先上更稳谁先上）。
  打平就沿用原来的站位顺序，保证选择确定。
- **往哪撤**（它是守方时，两版同）：按落脚点的**归属概率**（安全的后方）、落脚地本身的分（城池 3000，
  还回血快）、以及欠下的行动力（退得越远，下回合越迈不开腿）综合挑一个。撤退不是无谓逃跑：撤完要落在
  归属概率高、而且**当下就安全**的落脚点上；"退无可退"时（`escape_routes == 0`）连撤退按钮都不给，
  只能死战。


> **攻方那一边还是老规矩**：`ai.py` 的 `atk_should_hold` 仍按"不输就压上去"判断，所以
> 强攻推演里对守将行为的假设（`tactics.defender_stands_firm`）还是老模型，和守方自己的
> 新判断**不是同一套账**。守方这一支（`defense.ai_should_hold`）已经是新的了。

### 你和它在同一场交战里

决定权跟着阵营走，不跟着"谁在进攻"走：电脑进攻你驻守的那一格时，
**谁先出阵、继续还是撤退、往哪撤都还是你点**；轮到它做决定时，交战屏会等它（约 0.4 秒一步）。
它自己打完的交战会自动回到战场，你参与的那些仍然由你点"返回战场"。

交战屏上的三个"守方选择"和攻方的"继续还是收手"，都由**做决定那一方的版本**来算，
所以菊对梅时两边各用各的账（分派在顶层 `ai.py`，见开头）。

### 改完AI之后怎么知道它真的变强了

改 `ju/` 里的东西，跑：

```
python ai_match.py --a 菊 --b 竹 --games 10
```

看最后那行"**菊对竹的胜率**"。同种子配对 + 红蓝轮换，所以这个数已经尽量剥离了运气和先手；
但样本小的时候仍会抖。

改 `mei/ lan/ zhu/` 里的东西要特别小心：它们已经被固定为**参照版**。
兰稳定于10月13日
竹稳定于10月27日

#### 四版基准评测（2026-10-27）

三个稳定版（梅兰竹），两两之间。
跑法是三对循环赛、每对 20 局，六对都用**同一批种子**

10月27日评测比分：

| 对局 | 比分（A : B） | A 胜率 |
|---|---|---|
| 兰 vs 梅 | 14 : 6 | 兰 70.0% | 全歼 5 · 回合用尽 15
| 竹 vs 梅 | 20 : 0 | 竹 100.0% | 全歼 20 · 回合用尽 0
| 竹 vs 兰 | 19 : 1 | 竹 95.0% | 全歼 18 · 回合用尽 2
| 竹 vs 兰 | 85 : 15 | 竹 85.0% | 竹胜回合用尽 4 · 兰胜全歼 5 · 兰胜回合用尽 10

**怎么用这张表当准则**：升级菊后，能够保持对梅和兰的几乎全胜胜率，对竹也要有优势。

#### 三版算力开销（2026-10-27）

梅、兰、竹两两各打 6 局（三对共 18 局，同一批种子、红蓝互换），测每版 AI 自己花掉的**计算时间**。
跑法是 `python ai_time.py --versions 梅,兰,竹 --games 6`（这个脚本就是干这个的，见上面「文件构成」）。
计时挂在**顶层入口**上（顶层 `ai.py` 分派时调的那几个：`map_step` / `atk_should_hold` /
`defense.ai_should_hold / ai_pick_defender / ai_pick_retreat`），并加了一道"嵌套不重复计"的闸
——搜索内部也会调同一批函数（比如 `map_step` 推演时调 `ai_pick_defender`），那些已经被外层的
`map_step` 计进去了，不该再算一遍。

逐对（各 6 局）：

| 对局 | 6 局墙钟 | 梅 AI | 兰 AI | 竹 AI |
|---|---|---|---|---|
| 梅 vs 兰 | 108.1s | 48.6s | 59.4s | — |
| 梅 vs 竹 | 91.3s  | 61.1s | — | 30.0s |
| 兰 vs 竹 | 110.4s | — | 74.4s | 35.8s |

逐版（每版出场 12 局）：

| 版本 | AI 总时 | **每局** | 调用次数 | 每次 | 占墙钟 | 胜 |
|---|---|---|---|---|---|---|
| 梅 | 109.7s | **9.1s** | 2867 | 38.26ms | 35.4% | 1 |
| 兰 | 133.9s | **11.2s** | 4172 | 32.09ms | 43.2% | 5 |
| 竹 | 65.9s  | **5.5s** | 6363 | 10.35ms | 21.3% | 12 |

- **竹是战绩和效率双优** 已完成优化目标。
- **墙钟几乎全是 AI 计算**：三版占比相加 ≈ 100%。

### 它现在还不擅长什么

它把**这一回合**真正模拟着走一遍（先动谁、后动谁、交错走法都在搜索树里比过），但看不了
**跨回合的长期计划**——比如"这个城池里堆着两名守将，我先磨他三个回合再总攻"这种仗它看不到。
所以碰上**死守不出的对手**，它多半是把对方围在城里、靠地盘分赢下来，而不是硬啃。
搜索是宽搜 + 剪枝（`BEAM` / `BRANCH` / `DEPTH`），广度有限，所以是"这一回合的最优一步"，
不是全盘最优。

**攻守两边还不是同一套账。** 守方决策已按"本格/周围格子的归属概率"重构（见上），
但强攻推演里对守将的假设仍是老模型（`tactics.defender_stands_firm`），所以攻方可能误判
守将何时撤、何时死战。等这一步也换成归属概率的账，两边再合回一套。

**计谋它一概不用。** 这一版计谋的规则和界面都是齐的（见上面「计谋」一节），
但 `<版本>/ai.py` / `defense.py` / `offense.py` 里还没做计谋决策，所以 1P 模式下电脑只会按老一套
走位、进攻、吃粮——智力对它来说仍然只是个展示用的数字。

## 七、对局录像（复盘）

**每一局有电脑参与的对战都会自动留一份录像**，写成一个 JSONL 文件存在 `replays/` 下，
**边打边写**（写完一行就 flush），所以游戏中途关了、崩了，文件里也已经记到那一步；
一局正常结束时，这份文件就是一整局的完整记录。以后想复盘，直接看它就行。

看录像：

```
python replay.py replays/20261010-213508-001-s1-菊vs梅.jsonl           # 完整复盘
python replay.py replays/20261010-213508-001-s1-菊vs梅.jsonl --brief   # 只看每回合快照和终局
python replay.py replays/20261010-213508-001-s1-菊vs梅.jsonl --gui     # 开窗口，一步步看棋盘
```

复盘长这样（节选）：

```
=== 录像 s1 · 两人同机 · 蜀=菊　魏=梅 · 2026-10-10 21:35:08 ===

--- 第 1 / 100 回合 · 蜀（菊） ---
  蜀  张翼(6,1)100/3、马超(9,4)100/3、…          ← 名字(行,列)体力/移动力；☠=阵亡，*=守城加成
  魏  夏侯渊(3,2)100/3、荀彧(2,5)100/3、…
  蜀 55400（将 39200 地 16200）　｜　魏 60000（将 37600 地 22400）　｜　争夺 1 格
  > 张翼 移动 1 格 → 剑阁(5, 1)，剩移动力 2
  > 张翼 进攻 汉中（守军：贾诩）
    ⚔ 交战于 汉中（城池）：张翼 进攻 贾诩
      · 第 1 回合：张翼 -12（→88）　贾诩 -15（→105）
      · 张翼 继续缠斗
      · 贾诩（守方）选择撤退
        ↳ 撤 3 格到 天水（透支下回合 3 点行动力）
    ⚔ 收场（汉中（城池））：贾诩 撤到 天水，判为败方；张翼 占上风。
```

**记了些什么**（JSONL 每行一个事件，`k` 是类型）：

| 事件 | 内容 |
| --- | --- |
| `header` | 种子、模式、双方电脑版本、地图、名册——只写一次，复盘时重建地图用 |
| `turn` | **每回合开局的全盘快照**：所有武将（体力/位置/移动力/欠账）+ 粮草 + 比分 |
| `act` | 棋盘动作：走（含从哪到哪、剩多少移动力、顺路搬的粮）、吃粮、进攻、用计（含成功率与掷点） |
| `battle` | 交战子事件：开打、点将、每回合掉的体力、续战/撤退的选择、撤退落地、收场 |
| `grain` | 城池入库 |
| `end` | 胜方 + 最终比分 |

**几个约定**：

- 只有**有电脑参与**的局才录（1P、`ai_match.py`、两个 AI 对打）；2P 纯人对战不录。
- 录像**不碰 `game.rng`**，所以开不开录像，同一局跑出来一模一样（`smoke_test` 的
  逐字节回归不受影响）。
- `replays/` 已在 `.gitignore` 里（每局一堆，不进版本库）；想留哪一局就单独存一份。

### 图形复盘（`--gui`）

`--gui` 开一个窗口，把整局在棋盘上一格一格放出来，**不用进交战屏**——交战就是这个
棋盘上的一次掉血，攻守双方的血条随每一步变。想一步步看双方的每个动作：

```
python replay.py replays/xxx.jsonl --gui
```

| 按键 | 作用 |
| --- | --- |
| `→` / `←` | 推进 / 回退**一个动作**（按住可连翻） |
| `PgDn` / `PgUp` | 直接跳到下一 / 上一个回合的开局 |
| `空格` | 自动播放 / 暂停（约每 0.27 秒一步） |
| `Home` / `End` | 跳到开局 / 终局 |
| `Esc` / `Q` | 退出（关窗口也行） |

画面上：移动与撤退画一支黄箭头（从哪到哪），进攻的目标格套红框，交战的每一步在武将
头顶飘一个 `-12` 的掉血数，吃粮飘 `+3`，阵亡打 `☠`。右侧是本步说明、比分板（跟对局里
那块一模一样）、交战双方的血条，以及一根进度条。棋盘是按**录像头部那天的地图和名册**
重建的（`Game.for_replay()`，不读当前的配置文件），所以之后改 `map.txt` / `generals.txt`
也不会把老录像画歪，配置坏了照样能看。

> 图形复盘要 `pygame`；文字复盘（不带 `--gui`）只用标准库。没装 pygame 时 `--gui`
> 会提示一句，然后照旧能用文字复盘看。
>
> 两处**事件本身没记全**，图形复盘只能按下不表（下一条 `turn` 快照会自动校正）：
> 内讧互砍掉多少血（只记了一句说明文字），调虎离山调走的是哪一名敌将（只记了格子）。
> 这两种计谋眼下只有人类玩家会用，而 AI 的录像里一次都没出现（AI 还不做计谋决策），
> 所以正常复盘碰不到。
